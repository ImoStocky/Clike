IFJ language grammar
====================

The parser is recursive descent, split in two layers:

  1. LL(1) for the program, functions, and statements (parse_program /
     parse_func / parse_stmt in syntal.c).
  2. Pratt / precedence climbing for expressions (parse_expr … parse_primary).
     In the LL grammar, EXPR is a terminal: when the LL parser expects an
     expression it hands the current token to the expression parser.

Lookahead is one token. Alternatives of a nonterminal never share a FIRST
token. Epsilon rules use FOLLOW. The dangling-else conflict is resolved by
always binding else to the nearest if (prefer the else alternative over eps).

Tokens (terminals)
------------------
  type keywords:  auto  int  double  string
  control:        if  else  for  while  do  return  try  catch  throw  cin  cout
  literals:       INT  REAL  STRING
  id
  operators:      + - * / %  == != < > <= >=  && || !  =  << >>
  punctuation:    ( ) { } , ;
  $               end of file

auto is a syntactic type. Using it as a function return type or parameter
type is a semantic error (SEM_OTHER_ERR), not a syntax error.


1. Program and functions
------------------------

  0   PROG        -> FUNC PROG_N
  1   PROG_N      -> FUNC PROG_N
  2   PROG_N      -> eps                          FOLLOW = { $ }

  3   FUNC        -> TYPE id ( FD_PARAM ) FUNC_REST

  4   FD_PARAM    -> eps                          FOLLOW = { ) }
  5   FD_PARAM    -> TYPE id FD_PARAM_N
  6   FD_PARAM_N  -> , TYPE id FD_PARAM_N
  7   FD_PARAM_N  -> eps                          FOLLOW = { ) }

  8   FUNC_REST   -> ;
  9   FUNC_REST   -> BLOCK

A program is one or more functions. FUNC_REST ; is a forward declaration
(no body). FUNC_REST BLOCK is a definition. Nested functions are illegal
because FUNC is only derived from PROG.


2. Statements
-------------

 10   BLOCK       -> { STAT_LIST }
 11   STAT_LIST   -> STAT STAT_LIST
 12   STAT_LIST   -> eps                          FOLLOW = { } }

 13   STAT        -> BLOCK
 14   STAT        -> ;
 15   STAT        -> TYPE id VAR_DEF ;
 16   STAT        -> if ( EXPR ) STAT ELSE_OPT
 17   STAT        -> for ( FOR_INIT EXPR_OPT ; FOR_ITER ) STAT
 18   STAT        -> while ( EXPR ) STAT
 19   STAT        -> do STAT while ( EXPR ) ;
 20   STAT        -> try STAT catch ( string id ) STAT
 21   STAT        -> throw EXPR ;
 22   STAT        -> return EXPR_OPT ;
 23   STAT        -> cin >> id ID_LIST
 24   STAT        -> cout << EXPR COUT_TAIL
 25   STAT        -> id STAT_ID                   /* factor id */

 26   STAT_ID     -> = EXPR ;
 27   STAT_ID     -> ( ARGS ) ;

 28   ELSE_OPT    -> else STAT
 29   ELSE_OPT    -> eps                          FOLLOW = FIRST(STAT) U { } , $ }
                                                    minus { else }

 30   VAR_DEF     -> eps                          FOLLOW = { ; }
 31   VAR_DEF     -> = EXPR

 32   FOR_INIT    -> TYPE id VAR_DEF ;
 33   FOR_INIT    -> id = EXPR ;
 34   FOR_INIT    -> ;

 35   EXPR_OPT    -> EXPR
 36   EXPR_OPT    -> eps                          FOLLOW = { ; }

 37   FOR_ITER    -> id = EXPR
 38   FOR_ITER    -> eps                          FOLLOW = { ) }

 39   ID_LIST     -> >> id ID_LIST
 40   ID_LIST     -> ;                            FOLLOW after last id = { ; }

 41   COUT_TAIL   -> << EXPR COUT_TAIL
 42   COUT_TAIL   -> ;

 43   TYPE        -> auto | int | double | string

Notes
  - if / while / for / do bodies are STAT, so a single statement or a block
    is allowed (unlike the old grammar, which used a bare EXPR after if).
  - Assignment always ends with ;.
  - id is factored: = starts an assignment, ( starts a call statement.
    There is no other statement that starts with id, so this is LL(1).
  - for matches C-like optional parts: empty init, empty condition, empty
    increment. Increment, if present, is only id = EXPR (as implemented).
  - return may omit the expression (return ;).
  - throw accepts an expression, but its runtime value must be string.
  - catch accepts only a string variable. It catches explicit throws only;
    interpreter errors such as division by zero remain process-level errors.
  - Empty statement ; is a no-op.


3. Expressions (precedence grammar)
-----------------------------------
Lowest to highest binding. Binary operators are left-associative.
Unary operators are right-associative.

  EXPR     -> OR

  OR       -> AND OR'
  OR'      -> || AND OR' | eps

  AND      -> EQ AND'
  AND'     -> && EQ AND' | eps

  EQ       -> REL EQ'
  EQ'      -> == REL EQ' | != REL EQ' | eps

  REL      -> ADD REL'
  REL'     -> < ADD REL' | > ADD REL' | <= ADD REL' | >= ADD REL' | eps

  ADD      -> MUL ADD'
  ADD'     -> + MUL ADD' | - MUL ADD' | eps

  MUL      -> UNARY MUL'
  MUL'     -> * UNARY MUL' | / UNARY MUL' | % UNARY MUL' | eps

  UNARY    -> - UNARY | ! UNARY | PRIMARY

  PRIMARY  -> INT | REAL | STRING
            | id CALL_OPT
            | ( EXPR )

  CALL_OPT -> ( ARGS ) | eps                      FOLLOW = operators, ; , ) , ,

  ARGS     -> eps                                 FOLLOW = { ) }
  ARGS     -> EXPR ARGS_N
  ARGS_N   -> , EXPR ARGS_N | eps                 FOLLOW = { ) }

Operator precedence (high → low)
  unary  - !
  * / %
  + -
  < > <= >=
  == !=
  &&
  ||

Call vs identifier in an expression is the same id factoring as statements:
after id, ( means a call, anything else means a variable.

5. What the old draft got wrong
-------------------------------
  - STAT_N had two productions under one number (eps and STAT STAT_N).
  - Assignment id = EXPR had no semicolon.
  - if/else bodies were EXPR, so return / cin / assignment after if were
    illegal.
  - id always meant assignment; foo(1); could not be derived.
  - for required a typed declaration, both expressions, an increment
    assignment, and a block body.
  - while/do existed in the draft but not in the scanner token list; they
    are now first-class keywords.
  - EXPR was a black-box token with no operator grammar.
  - Function-call arguments were missing in both statements and expressions.
